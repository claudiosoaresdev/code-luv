# Plano 5 — Módulo de CSS: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A aluna passa a estilizar o próprio site: as aulas de CSS têm um editor só de CSS, o resultado mostra o site dela (ou um site de exemplo) com o CSS aplicado, a conferência lê as regras que ela escreveu, e "Meu site" junta o HTML e o CSS de todas as aulas concluídas. Entram as seis aulas do módulo: cores, letras, espaçamento e bordas, organização com flexbox, site no celular e pequenos movimentos.

**Architecture:** As aulas ganham um segundo módulo (`modulo: 'css'`), e o tipo `Aula` vira uma união discriminada: aula de HTML confere com `CheckHtml` (DOMParser, como hoje), aula de CSS confere com `CheckCss` (regras lidas com `css-tree`). Um despachante `conferir(aula, codigo)` escolhe o conferidor. `montarSite` passa a devolver `html` e `css` separados e aceita o código em edição; `documentoDoSite` junta os dois num documento para o `iframe` (`<style>` + HTML). A prática de CSS mostra o site inteiro com o CSS da aula no lugar dele e oferece "Ver como celular". As aulas são conteúdo (`aula.ts` + `explicacao.mdx`), como no módulo de HTML.

**Decisões deste plano (tomadas com a responsável pelo produto em 2026-10-09):**

- **Editor de CSS separado.** Na aula de CSS, o editor é só de CSS ("Seu código CSS"). O HTML do site dela já vem pronto, e o resultado mostra os dois juntos — como um site de verdade (`index.html` + `style.css`).
- **Conferência pelas regras escritas.** A conferência lê o CSS: "existe uma regra para `h1` com `color`". Previsível, testável e fácil de explicar numa pista.
- **Plataforma e as seis aulas** no mesmo plano.

**Decisões técnicas (e por quê):**

- **`css-tree` para ler o CSS**, nos testes e no navegador. O jsdom não calcula estilos de verdade, e o DOMParser não garante folhas de estilo em documentos inertes; um parser puro dá o mesmo resultado nos dois lugares. Custa ~57 kB (gzip) na rota da aula — aceito; se pesar, carregar sob demanda depois.
- **Declaração com valor inválido não conta**, como no navegador (`lexer.matchDeclaration`). Assim `colr: red` ou `color: red background: blue` (faltou o ponto e vírgula) não passam na conferência — e o resultado também não muda. A conferência e o resultado contam a mesma história.
- **Seletor comparado depois de normalizado** (`css-tree` gera o texto sem espaços extras; minúsculas). `h1, h2 { … }` vale para `h1` e para `h2`. `UL > LI` casa com `ul > li`.
- **Cada aula de CSS acrescenta regras**, como cada aula de HTML acrescenta uma parte. O site junta o CSS das aulas concluídas, na ordem das aulas.
- **Resultado da prática de CSS = site inteiro**, com o código do editor no lugar desta aula (`montarSite(…, { slug, codigo })`). Sem HTML concluído, entra o **site de exemplo** (as soluções das aulas de HTML), com um aviso.
- **"Ver como celular"** (`Toggle` com `aria-pressed`) deixa o `iframe` com 360px. A aula 5 usa `@media (max-width: 400px)`: a coluna da prática no notebook passa de 400px, e o celular simulado fica abaixo.
- **`ordem` é a posição dentro do módulo.** `AULAS` fica ordenada por módulo (HTML antes de CSS) e depois por `ordem`. Os rótulos passam a dizer o módulo: "Aula 1 · CSS", "Aula 1 de CSS · Cores".

**Convenções do repositório:** Prettier sem ponto e vírgula, aspas simples, `trailingComma: 'all'`; ESLint ordena imports; testes em `src/**/*.spec.{ts,tsx}` importando de `vitest` (`globals: false`, jest-dom + cleanup em `vitest.setup.ts`, `restoreMocks: true`); commits Conventional Commits em minúsculas com o trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; área de toque mínima 48px; links com cara de botão = `<Link className={buttonVariants()}>`; Base UI usa `render`, não `asChild`. `src/lib/checks/run-css-checks.ts`:

```ts
import * as csstree from 'css-tree'

import type { CheckCss, CheckResult } from './types'

type Regra = {
  seletores: string[]
  emMidia: boolean
  declaracoes: { propriedade: string; valor: string }[]
}

function normalizarSeletor(texto: string) {
  return csstree
    .generate(csstree.parse(texto, { context: 'selector' }))
    .toLowerCase()
}

/**
 * Lê as regras como o navegador: declaração com valor inválido não conta
 * (DS-14). Erros de sintaxe não interrompem a leitura.
 */
function lerRegras(css: string): Regra[] {
  const regras: Regra[] = []
  const ast = csstree.parse(css, { onParseError: () => {} })
  csstree.walk(ast, {
    visit: 'Rule',
    enter(node) {
      if (node.prelude.type !== 'SelectorList') return
      const declaracoes = node.block.children.toArray().flatMap((item) =>
        item.type === 'Declaration' &&
        !csstree.lexer.matchDeclaration(item).error
          ? [
              {
                propriedade: item.property.toLowerCase(),
                valor: csstree.generate(item.value).trim().toLowerCase(),
              },
            ]
          : [],
      )
      regras.push({
        seletores: node.prelude.children
          .toArray()
          .map((seletor) => csstree.generate(seletor).toLowerCase()),
        emMidia: this.atrule?.name === 'media',
        declaracoes,
      })
    },
  })
  return regras
}

function passa(regras: Regra[], check: CheckCss) {
  const alvo = normalizarSeletor(check.seletor)
  return regras.some(
    (regra) =>
      (!check.emMidia || regra.emMidia) &&
      regra.seletores.includes(alvo) &&
      regra.declaracoes.some(
        (d) =>
          check.propriedades.includes(d.propriedade) &&
          (check.valor === undefined || d.valor === check.valor.toLowerCase()),
      ),
  )
}

/** Confere o CSS da aluna pelas regras escritas (aulas do módulo de CSS). */
export function runCssChecks(css: string, checks: CheckCss[]): CheckResult[] {
  const regras = lerRegras(css)
  return checks.map((check) => ({
    descricao: check.descricao,
    ok: passa(regras, check),
  }))
}
```

Se o TypeScript reclamar do `this` dentro de `enter` (tipos de `@types/css-tree`), mantenha `enter` como `function` (não arrow) — o `this` é o `WalkContext`, que tem `atrule`. Se `matchDeclaration` não existir nos tipos, confira `node_modules/@types/css-tree/index.d.ts` (a função existe no `lexer` em tempo de execução — verificado com `css-tree@3.2.1`).

```ts
/** Código que a aluna está editando agora (resultado da prática de CSS). */
export type EmEdicao = { slug: string; codigo: string }

/**
 * "Meu site" (HU-07): o HTML das aulas de HTML concluídas e o CSS das aulas
 * de CSS concluídas, cada um na ordem das aulas. Com `emEdicao`, aquela aula
 * entra com o código do editor, mesmo sem estar concluída.
 */
export function montarSite(p: Progresso, aulas: Aula[], emEdicao?: EmEdicao) {
  const codigoDe = (aula: Aula) =>
    emEdicao && aula.slug === emEdicao.slug
      ? emEdicao.codigo
      : (p.aulas[aula.slug]?.codigoConcluido ??
        p.aulas[aula.slug]?.codigo ??
        '')
  const entram = aulas.filter(
    (aula) => aula.slug === emEdicao?.slug || concluida(p, aula),
  )
  const juntar = (modulo: Aula['modulo']) =>
    entram
      .filter((aula) => aula.modulo === modulo)
      .map((aula) => codigoDe(aula).trim())
      .filter(Boolean)
      .join('\n\n')
  return {
    html: juntar('html'),
    css: juntar('css'),
    partes: aulas
      .filter((aula) => concluida(p, aula))
      .map(({ slug, titulo }) => ({ slug, titulo })),
  }
}

/**
 * O documento do iframe: o CSS num <style> antes do HTML. Sem CSS, é o HTML
 * como está. `htmlDeExemplo` entra quando a aluna ainda não tem HTML.
 */
export function documentoDoSite(
  site: { html: string; css: string },
  htmlDeExemplo = '',
) {
  const corpo = site.html || htmlDeExemplo
  if (!site.css) return corpo
  // "</style" dentro do CSS fecharia a tag; para o CSS, "<\/style" é o mesmo texto.
  const css = site.css.replace(/<\/style/gi, '<\\/style')
  return `<style>\n${css}\n</style>\n${corpo}`
}
```

````mdx
## O que é CSS

O HTML diz o que cada coisa é. O **CSS** diz como cada coisa aparece: cor, tamanho, espaço e lugar na tela.

A propriedade `color` muda a cor do texto. A propriedade `background-color` muda a cor do fundo.

O valor pode ser o nome de uma cor em inglês, como `pink` ou `purple`. Existem mais de cem nomes prontos.

Escolha cores com bastante diferença entre o texto e o fundo. Assim todo mundo consegue ler.

## Exemplo

```css
body {

}

h1 {
  color: purple;
}
```

A regra do `body` vale para a página inteira. A regra do `h1` vale só para os títulos.
````

````mdx
## Toda tag é uma caixa

Para o CSS, cada tag na página é uma caixa. Até um título ou um parágrafo.

Em volta do conteúdo, a caixa tem três camadas: o espaço de dentro, a borda e o espaço de fora.

## Espaço de dentro e de fora

O `padding` é o espaço de dentro, entre o conteúdo e a borda. Pense na margem branca em volta de uma foto num quadro.

A `margin` é o espaço de fora, que afasta a caixa das vizinhas.

Os dois usam medidas como `16px`. Um pixel é um pontinho da tela.

## Bordas

A propriedade `border` desenha a borda. Ela recebe três valores: a grossura, o estilo e a cor.

Por exemplo, `2px solid purple` é uma borda de dois pixels, contínua e roxa.

A propriedade `border-radius` arredonda os cantos. Quanto maior o número, mais redondo.

## Exemplo

```css
body {
  padding: 24px;
}

img {
  border-radius: 16px;
}

form {
  border: 2px solid purple;
  padding: 16px;
}
```
````

````mdx
Em telas largas, um texto que vai de uma ponta à outra cansa os olhos. A propriedade `max-width` limita a largura de uma caixa.
````

````mdx
## Quando o mouse passa por cima

O seletor `a:hover` vale para um link só enquanto o mouse está em cima dele. O `:hover` funciona com qualquer tag.

É um jeito de mostrar que aquilo pode ser clicado.

## Mudar devagar

Sem nada, a cor troca de uma vez. A propriedade `transition` faz a troca acontecer aos poucos.

Ela recebe o nome da propriedade que muda e o tempo. Por exemplo, `color 0.3s` quer dizer que a cor muda em três décimos de segundo.

A `transition` fica na regra normal, e não na regra do hover. Assim a cor muda devagar na ida e na volta.

## Movimento com cuidado

Algumas pessoas passam mal com coisas que se mexem na tela. Prefira movimentos curtos e suaves, como uma troca de cor.

## Exemplo

a {
  color: purple;
  transition: color 0.3s;

a:hover {
  color: deeppink;
}

Passe o mouse no link do resultado para ver a cor mudar.
````
